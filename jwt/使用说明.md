# JWT 令牌管理器使用说明

## 设计边界与核心保证

`jwt` 包提供围绕业务会话生命周期构建的 JWT 身份认证能力，构造后配置完全不可变，并严格执行以下安全契约：

1. **算法与声明强约束**：仅接受 `HS256`，强制要求合法 `exp`，所有注册声明（`sub`/`iss`/`aud`/`exp`/`nbf`/`iat`/`jti`/`type`/`sid`）执行严格类型检查，禁止 `CustomClaims` 覆盖保留字段。
2. **严格的令牌用途隔离（Token Type Isolation）**：
   - `Authenticate` 与 `ValidateAccessToken` **只接受 `AccessToken`**；若传入 `RefreshToken`，立即返回 `ErrTokenTypeMismatch`，从根源上杜绝刷新令牌被当作业务 API 访问凭证使用。
   - `ValidateRefreshToken` 与 `RefreshTokenPair` **只接受未消费、未吊销的 `RefreshToken`**。
3. **原子 Refresh Rotation 与防重放**：
   - 每次刷新一次性消费旧 `RefreshToken` 的 `jti`，签发共享同一 `SessionID` 的新令牌对。
   - 新令牌对在触碰外部存储前先在内存中完成预生成校验；若后续吊销存储瞬时故障，支持 `RefreshTokenUseReleaser` 的存储自动回滚，合法客户端重试不会误触重放封禁。
   - 一旦检测到已轮换的旧 `RefreshToken` 被重放，默认立即吊销整个 `SessionID`，使该会话下所有令牌失效。
4. **验证缓存不破坏认证正确性**：
   - O(1) LRU 缓存**只缓存验证通过的 `AccessToken`**，绝不缓存失败结果（避免时钟微小偏差下 `nbf` 未生效令牌被长期负缓存锁死，也防止攻击者随机伪造 token 挤占正常缓存）。
   - 缓存 map key 仅存原始 JWT 的 SHA-256 摘要（`[32]byte`），不持有原始 JWT 字符串；有效期 `validUntil = min(now + CacheTTL, token.exp)`，命中后仍实时校验 token/session 吊销状态；所有返回声明均为深拷贝副本。
5. **多密钥轮换（`kid`）**：
   - 配置 `JWTOptions.SigningKeyID` 后，新签发令牌会在 JWT Header 写入 `kid`，验签时严格按 `kid` 路由到当前签名密钥或 `VerificationKeys` 中的历史密钥；若需在迁移期兼容无 `kid` 旧令牌，可配置 `LegacyVerificationKey`。
   - 刷新轮换时自动用新主密钥与 `SigningKeyID` 签发新令牌对，实现平滑升级。
6. **按需后台清理**：
   - 仅当 `BlacklistCleanInterval > 0` 且至少存在内存清理需求（启用了缓存，或吊销/消费存储实现了对应 `Cleaner` 接口）时才启动后台清理协程。

## 推荐标准工作流（6 步完成完整认证生命周期）

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"

	"github.com/iwen-conf/utils-pkg/jwt"
)

func main() {
	// 1. 创建管理器（密钥至少 32 字节，建议由 KMS 或环境变量注入）
	opts := jwt.DefaultJWTOptions()
	opts.Issuer = "my-auth-service"
	opts.ExpectedIssuer = "my-auth-service"
	opts.AccessTokenExpiry = 15 * time.Minute
	opts.RefreshTokenExpiry = 7 * 24 * time.Hour

	tm, err := jwt.NewTokenManager("0123456789abcdef0123456789abcdef", opts)
	if err != nil {
		panic(err)
	}
	defer tm.Shutdown()

	ctx := context.Background()

	// 2. 登录签发：根据统一业务身份生成 Access + Refresh 令牌对（自动生成 CSPRNG SessionID）
	pair, err := tm.IssueTokenPair(jwt.Identity{
		Subject:      "user-1001",
		ActorType:    "user",
		TenantID:     "tenant-01",
		Roles:        []string{"author"},
		Scopes:       []string{"articles:write"},
		CustomClaims: map[string]interface{}{"login_channel": "web"},
	})
	if err != nil {
		panic(err)
	}

	// 3. 请求鉴权：验证 AccessToken 并直接提取业务身份（无需重复传 TokenProfile）
	identity, claims, err := tm.Authenticate(ctx, pair.AccessToken)
	if err != nil {
		panic(err)
	}
	fmt.Printf("鉴权通过: sub=%s actor=%s sid=%s\n", identity.Subject, identity.ActorType, claims.SessionID)

	// 4. 安全刷新：轮换获取完整的新 TokenPair（务必将新的 RefreshToken 返回客户端替换旧值）
	newPair, err := tm.RefreshTokenPair(ctx, pair.RefreshToken)
	if err != nil {
		if errors.Is(err, jwt.ErrRefreshReuseDetected) {
			// 检测到旧 RefreshToken 被重放，整个会话已被自动封禁
		}
		panic(err)
	}

	// 5. 单令牌吊销（仅作废某一个具体令牌）
	if err := tm.RevokeToken(ctx, pair.AccessToken); err != nil {
		panic(err)
	}

	// 6. 会话注销 / 后台踢人：既可传令牌（RevokeSession），也可直接传会话 ID（无需保存原始 JWT）
	if err := tm.RevokeSessionByID(ctx, newPair.SessionID); err != nil {
		panic(err)
	}
}
```

## 密钥轮换示例（`kid`）

```go
opts := jwt.DefaultJWTOptions()
opts.SigningKeyID = "key-2026-11"
opts.VerificationKeys = map[string][]byte{
	"key-2026-10": []byte(os.Getenv("JWT_PREV_SECRET")), // 历史密钥继续可验签
}
opts.LegacyVerificationKey = []byte(os.Getenv("JWT_LEGACY_SECRET")) // 可选：迁移期兼容无 kid 旧令牌

tm, err := jwt.NewTokenManager(os.Getenv("JWT_ACTIVE_SECRET"), opts)
```

## 自定义身份字段映射（`TokenProfile`）

若业务已有历史 JWT 字段命名规范，可在初始化时一次性配置 `TokenProfile`。验证后调用 `tm.Authenticate` 或 `claims.Identity()` 均会自动按该配置还原身份，无需在每个中间件重复传参：

```go
opts := jwt.DefaultJWTOptions()
opts.TokenProfile = &jwt.TokenProfile{
	ActorTypeClaim: "kind",
	ActorIDClaim:   "principal",
	TenantIDClaim:  "org_id",
	RolesClaim:     "role_codes",
	ScopesClaim:    "permissions",
}
```

> `TokenProfile` 字段名不得占用 JWT 保留键（`iss`/`sub`/`aud`/`exp`/`nbf`/`iat`/`jti`/`type`/`sid`），也不得彼此重复，否则 `NewTokenManager` 将在构造阶段立即返回 `ErrReservedClaimKey` 或 `ErrDuplicateClaimKey`。

## 多实例部署与外部存储契约

默认情况下，`TokenManager` 使用 `MemoryRevocationStore` 和 `MemoryRefreshTokenUseStore`，**仅适用于单进程部署**。

在多实例（多副本）生产环境中，**必须**注入共享外部实现：

1. **`RevocationStore`**：按 `expiresAt`（TTL）存储不透明哈希键 `key`（`TokenManager` 已完成 SHA-256 摘要，外部存储不会接触原始 JWT）。外部存储错误会按失败关闭（Fail-Closed）拒绝验证。
2. **`RefreshTokenUseStore`**：`Consume(ctx, jti, expiresAt)` **必须使用单条原子原语实现**（例如 Redis `SET key 1 NX PX ttl`、数据库唯一键插入或串行化事务），**严禁使用非原子的 `GET` 再 `SET`**。可选实现 `RefreshTokenUseReleaser`（`Release(ctx, jti)`）以支持后续步骤异常时的回滚。

## 可控时钟与确定性测试

通过 `JWTOptions.Clock` 可注入自定义时间源（如 `func() time.Time`），同时作用于签发时间、JWT `exp`/`nbf` 解析、验证缓存 TTL 以及默认内存吊销/消费存储，无需在单元测试中使用脆弱的 `time.Sleep`。

## 常用错误判别（`errors.Is`）

| 错误变量 | 触发场景 |
| :--- | :--- |
| `ErrSecretKeyTooShort` | 签名或验证密钥不足 32 字节 |
| `ErrInvalidKeyID` / `ErrDuplicateKeyID` | `SigningKeyID` 或 `VerificationKeys` 存在空值或冲突定义 |
| `ErrUnknownKeyID` | 令牌携带未知/非法 `kid`，或在启用 `kid` 后缺少 `kid` 且未配置 `LegacyVerificationKey` |
| `ErrTokenTypeMismatch` | 将 `RefreshToken` 传给访问令牌验证接口，或将 `AccessToken` 传给刷新接口 |
| `ErrUnknownTokenType` | 令牌缺少 `type` 或包含未知类型 |
| `ErrTokenRevoked` | 令牌已被吊销或该刷新令牌已被轮换消费 |
| `ErrSessionRevoked` | 令牌所属会话（`sid`）已被注销或因重放被封禁 |
| `ErrRefreshReuseDetected` | 已消费的 `RefreshToken` 被再次提交（触发会话级封禁） |
| `ErrReservedClaimKey` | `CustomClaims` 或 `TokenProfile` 使用了 JWT 保留字段 |
| `ErrDuplicateClaimKey` | 自定义声明或身份映射键发生重复冲突 |
| `ErrInvalidTokenFormat` / `ErrTokenTooLarge` | 令牌格式非法或超过 `MaxTokenLength`（8192 字节） |
