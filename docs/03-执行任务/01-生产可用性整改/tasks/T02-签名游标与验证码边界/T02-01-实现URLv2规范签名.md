# T02-01 修复 F-SIGN-001 实现 URL v2 规范签名

状态：`[ ]`

## 来源

1. finding_id：F-SIGN-001。
2. Handoff：[URL 签名未绑定方法、主机和路径](../../../../08-安全审计/01-能力与安全评估交接/03-findings.md#f-sign-001--url-签名未绑定方法主机和路径)。
3. 权限类型：anonymous，前提是攻击者持有一个合法签名 URL。
4. 数据产量：BIZ/AUTH capability；具体影响由下游把签名 URL 用于什么资源决定。

## 目标

把签名对象从“时间戳 + query”升级为带显式版本的完整 canonical request。合法签名只能用于签发时的 HTTP method、scheme、host、path 和 query，移动到其他端点后必须失败。

## 项目定位对齐

1. 影响用户角色：匿名访问者、已登录用户和签名 URL 签发服务。
2. 影响信任边界：外部可控 URL 进入下游服务前的完整性校验边界。
3. 本库只证明 URL 未被篡改；业务授权、一次性消费和资源所有权仍由下游负责。

## 允许改动

1. `url/url.go` 中 `URLBuilder`、`Build`、`ValidateSignature`、`CreateSignedURL`、`BatchValidateSignatures` 及新增私有 canonical helper。
2. `url/url_test.go`，或新增 `url/signature_v2_test.go`。
3. 本任务可把现有测试密钥统一替换为至少 32 字节的固定测试值，但密钥长度的强制校验由 T02-02 完成。

## 禁止改动

1. 不实现 legacy v1 验证回退。
2. 不新增远程签名服务、密钥轮换服务、nonce 存储或数据库。
3. 不在本任务重写 `ParseURL`、`SerializeParams`、`DeserializeParams` 的通用行为。
4. 不把 fragment 纳入签名；fragment 不会发送给服务器。

## 当前行为

1. `generateSignature` 只签 `timestamp + encoded query`。
2. `ValidateSignature` 同样只重算 timestamp 和 query，因此合法签名可被搬到另一个 host/path。
3. 签名使用 `base64.StdEncoding`，没有显式格式版本。
4. `URLBuilder` 没有 HTTP method 字段，所有用途被隐式当成同一种请求。

## 固定目标 API

1. `URLBuilder` 增加私有字段 `method string`，`NewURLBuilder` 默认写入 `GET`。
2. 增加流式方法：

   ```go
   func (b *URLBuilder) SetMethod(method string) *URLBuilder
   ```

3. 保留现有默认 GET 验证入口：

   ```go
   func ValidateSignature(rawURL, secretKey string, maxAgeSeconds int64) (bool, error)
   ```

4. 新增按实际请求方法验证的权威入口：

   ```go
   func ValidateSignatureWithMethod(rawURL, method, secretKey string, maxAgeSeconds int64) (bool, error)
   ```

5. `ValidateSignature` 必须只调用 `ValidateSignatureWithMethod(rawURL, "GET", ...)`，不得复制一套算法。
6. `CreateSignedURL` 和 `BatchValidateSignatures` 保持默认 GET；本任务不新增批量 method API。

## 固定 canonical 规则

规范串必须严格按以下六行生成，行尾不额外追加换行：

```text
2
<UPPERCASE_METHOD>
<lowercase_scheme>
<lowercase_host_including_port>
<escaped_path_or_slash>
<canonical_query_without__sign>
```

1. 构建结果加入 `_sigv=2`。
2. method 先 `strings.TrimSpace` 再转大写；空 method 由 T02-02 拒绝。
3. scheme 和完整 `URL.Host` 转小写，端口保留，不移除默认端口。
4. path 使用 `URL.EscapedPath()`；空 path 固定为 `/`。
5. query 使用 `url.Values.Encode()`；删除全部 `_sign` 后编码，但保留 `_sigv`、`_ts`、`_exp` 和业务参数。
6. 签名为 `HMAC-SHA256(canonical)`，输出使用 `base64.RawURLEncoding`。
7. fragment 不进入 canonical，也不能影响验证结果。

## 输出

1. 单一私有 helper 负责 canonical request，Build 与验证共用。
2. 新签名 URL 明确包含 `_sigv=2`。
3. method/host/path/query 任意一个发生变化，验证返回 `ErrInvalidSignature`。
4. 默认 GET API 保持可用，非 GET 调用方使用新 API。

- [ ] 给 `URLBuilder` 增加默认 `GET` method 和 `SetMethod`，不改变其他流式 setter 的返回风格。
- [ ] 新增 `canonicalRequestV2(parsed *url.URL, method string) (string, error)` 或等价私有 helper，严格实现六行格式。
- [ ] 修改 `Build`：先组装完整 URL 和保留参数，再写 `_sigv=2`，删除旧 `_sign`，对 canonical 串签名，最后写入 `_sign`。
- [ ] 修改验证路径：提取签名后删除全部 `_sign`，调用同一个 canonical helper，再用恒定时间比较签名。
- [ ] `ValidateSignature` 变为 GET wrapper；新增 `ValidateSignatureWithMethod`。
- [ ] 保持 `CreateSignedURL`、`BatchValidateSignatures` 的默认 GET 语义，并确认它们走 v2 实现。
- [ ] 更新旧测试中对 base64 字符串或 query 的硬编码预期，不允许继续接受无 `_sigv` 的旧格式。

## 正向测试

1. GET URL 经 `Build` 后由 `ValidateSignature` 验证成功。
2. POST URL 经 `SetMethod("post")` 后由 `ValidateSignatureWithMethod(..., "POST", ...)` 成功。
3. method 大小写在规范化后等价，例如签发 `post`、验证 `POST`。
4. URL 中有重复业务 query 参数、已转义 path、显式端口时仍能稳定签发和验证。
5. 只修改 fragment 仍能验证成功，并在测试名中说明 fragment 不属于 HTTP 请求目标。

## 反向测试

1. 把签名 URL 的 `GET` 改按 `POST` 验证，返回 `ErrInvalidSignature`。
2. 修改 scheme、host、端口、path、任一 query 值或新增 query 参数，均返回 `ErrInvalidSignature`。
3. 把一个合法 URL 的 `_sign` 搬到另一个 path，即使 query 完全相同也失败。
4. 删除或修改 `_sigv` 的严格错误类型由 T02-02 补齐；本任务至少不得自动按旧算法成功。

## 不要做

1. 不在验证 v2 失败后尝试旧 `timestamp+query` 算法。
2. 不用字符串拼接原始 `rawURL` 代替结构化 canonical；原始 query 顺序和转义不能作为签名事实。
3. 不用 `path.Clean` 改写业务 path；签名使用 URL 已解析的 escaped path。
4. 不把 HMAC 相等比较改成普通字符串 `==`。
5. 不把业务授权写进本工具包。

## 完成标准

1. 旧实现可被 host/path/method 搬运测试稳定击穿，新实现全部拒绝。
2. Build 与 Validate 共用同一 canonical helper，没有两份格式规则。
3. v2 正反测试、race 和全量测试通过，结果写入进度表。
