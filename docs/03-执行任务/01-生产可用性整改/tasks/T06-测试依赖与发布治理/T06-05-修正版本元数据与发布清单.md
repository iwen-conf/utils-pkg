# T06-05 GOV-002 修正版本元数据与 v0.4.0 发布清单

状态：`[ ]`

## 来源

1. governance_id：GOV-002。
2. Handoff：[发布与供应链治理不足](../../../../08-安全审计/01-能力与安全评估交接/03-findings.md#gov-002--发布与供应链治理不足)。
3. 当前事实：HEAD/tag 为 `v0.3.0`，根 `Version()` 返回 `v0.2.8`。
4. 权限类型：maintainer/release-verifier。
5. 数据产量：版本识别与发布可重复性。

## 目标

把代码内版本元数据统一到目标候选 `v0.4.0`，用测试防止再次漂移，并创建不执行发布动作的详细发布清单。tag 仍是正式发布事实；未经授权不得创建。

## 前置

1. T06-04 已创建 CHANGELOG，并收录全部实际变更。
2. 除许可证决策外，公开 API 和文档不再变化。

## 允许改动

1. `main.go`。
2. 新增根 `main_test.go`。
3. `CHANGELOG.md`：把候选内容组织为 `v0.4.0` 待发布区，但不写虚假日期/链接。
4. 新增 `docs/06-环境运维/01-v0.4.0发布清单.md`，更新目录 README 索引。

## 禁止改动

1. 不运行 `git tag`、`git push`、`gh release create` 或发布命令。
2. 不把当前 HEAD 声称为已发布 v0.4.0。
3. 不从 Git runtime 动态读取 tag 作为库 API；模块消费者可能没有 .git。
4. 不选择或生成 LICENSE。

## 当前行为

1. 正式最高 tag 是 v0.3.0，但 Version() 仍返回 v0.2.8。
2. 根包没有版本测试，漂移不会触发门禁。
3. 没有项目内发布清单，授权点、许可证 gate 和发布后检查未落盘。

## 固定版本契约

1. `Version()` 返回精确字符串 `v0.4.0`。
2. `main_test.go` 至少断言精确值和合法 SemVer `^v[0-9]+\.[0-9]+\.[0-9]+$`。
3. 目标 tag 名固定 `v0.4.0`，但在用户授权前不存在。
4. CHANGELOG 保留顶层 `## [Unreleased]`，并把本轮候选内容放入固定标题 `## [0.4.0] - 待发布`；正式发布后才将“待发布”替换为日期。
5. 正式发布时再补日期和比较链接，不能提前伪造。

## 发布清单必须包含

1. 目标 commit SHA 和分支确认。
2. 工作树必须干净，除预期发布提交外无改动。
3. Go 1.24.x/stable CI 全绿。
4. test/race/vet/mod/coverage/govulncheck 的精确命令和预期。
5. CHANGELOG、README、AGENTS、迁移文档、Version 一致性。
6. LICENSE 决策状态；未决时明确“不可公开发布”。
7. 手工授权点：创建 annotated tag、push tag、创建 Release，三者均需用户明确批准。
8. 发布后验证：远端 tag、模块拉取、Version、文档链接。
9. 回滚/撤回说明：不得静默移动已公开 tag；出现问题应发布修复版本或按平台流程撤回。

## 正向测试

1. `Version()` 精确返回 v0.4.0。
2. SemVer 格式测试通过。
3. 发布清单可由另一个执行者逐项运行，不依赖聊天上下文。

## 反向验证

1. `git tag --points-at HEAD` 不应因本任务新增 v0.4.0。
2. 文档不说“v0.4.0 已发布”。
3. workflow 不包含 tag/release automation。
4. Version 不再出现 v0.2.8，目标文档不把 v0.3.0 当候选。

```bash
go vet ./...

```

## 不要做

1. 不把创建 tag 当作“验证版本”的必要步骤。
2. 不移动或删除已有 v0.3.0 tag。
3. 不自动填当天为发布日期。
4. 不在测试里调用 git 命令；Version 是纯库 API。
5. 不忽略许可证阻塞后宣称 public release ready。
