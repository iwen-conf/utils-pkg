## 当前行为

1. 只有开发者手工运行覆盖率，没有仓库内阈值脚本或 CI gate。
2. errors/slice/useragent 明显低于其文档宣称，且安全回归尚未统一映射。

## 固定阈值

阈值以 statement coverage 百分比计，保留一位小数：

| 范围 | 最低值 |
| --- | ---: |
| 全仓 aggregate | 75.0% |
| `errors` | 65.0% |
| `slice` | 80.0% |
| `useragent` | 80.0% |
| `jwt` | 80.0% |
| `crypto` | 80.0% |
| `url` | 80.0% |
| `captcha` | 90.0% |

1. 根包在 T06-05 添加版本测试；本脚本可不设根包独立阈值，但 aggregate 必须包含它。
2. 后续只能提高阈值；降低需要用户/维护者明确批准并在 CHANGELOG/测试文档说明。

## 固定脚本契约

文件 `.github/scripts/check-coverage.sh`：

1. POSIX 路径安全，bash 开头 `set -euo pipefail`。
2. 使用 `mktemp -d`，trap 清理；不把 coverage.out 留在仓库。
3. aggregate：`go test -count=1 -covermode=atomic -coverprofile=<tmp>/all.out ./...`，再用 `go tool cover -func` 读取 total。
4. 每个目标包单独生成 profile 并读取 total；不得解析本地化的人类日志猜测。
5. 以 awk 或 Go 小工具做数值比较；任何无法解析的值都失败，不默认 0/成功。
6. 输出每个范围的 `actual / required / PASS|FAIL`。
7. 支持环境变量覆盖以测试失败路径：`COVERAGE_MIN_TOTAL`、`COVERAGE_MIN_ERRORS` 等；CI 不设置时使用表中默认值。
8. 任一阈值未达退出非 0。

## 测试补齐优先顺序

1. 已知 finding 的利用/错误路径。
2. constructor invalid input 和 error wrapping。
3. 并发/生命周期 race。
4. legacy errors/validator 分支。
5. slice 全部公共函数边界（删除死代码后提高有效覆盖）。
6. User-Agent LRU、TTL、解析优先级和一致性。
7. 版本函数由 T06-05处理。

## 正向验证

1. 默认脚本输出所有包和 aggregate 均 PASS，退出 0。
2. CI coverage job 调用同一脚本，不复制阈值。
3. 新测试包含错误、边界和并发断言，不只是 happy path。

## 反向验证

1. 任意阈值设为 101 时脚本退出非 0。
2. profile 缺失或 total 无法解析时失败。
3. 删除一个关键测试导致包低于阈值时 CI 失败；验证后恢复。
4. 仓库无 `coverage.out`、临时目录或二进制残留。

## 验证命令

```bash
chmod +x .github/scripts/check-coverage.sh
.github/scripts/check-coverage.sh
if COVERAGE_MIN_TOTAL=101 .github/scripts/check-coverage.sh; then exit 1; fi
go test -race -count=1 ./...
go vet ./...
git diff --check
git status --short
```

## 不要做

1. 不通过降低 denominator、忽略包或删除生产分支追数字。
2. 不把随机性/时间测试写成易抖动的概率断言或长 sleep。
3. 不在 workflow 和脚本维护两份阈值。
4. 不因覆盖率达标就跳过 finding 回归测试。
5. 不提交 coverage 产物。

## 完成标准

1. 固定阈值全部达到，失败注入证明脚本真的会阻断。
2. CI 使用同一脚本，阈值只有一个事实来源。
3. errors/slice/useragent 的新增测试覆盖实际缺陷和边界。
4. race、vet、全量测试通过，进度表记录实际百分比。
