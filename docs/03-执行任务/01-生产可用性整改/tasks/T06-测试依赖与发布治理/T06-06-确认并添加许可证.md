## 解阻所需输入

用户必须明确提供：

1. `license_spdx`：例如 `MIT`、`Apache-2.0`，或明确“保持无许可证/不公开分发”。这里只是格式示例，不是推荐。
2. `copyright_holder`：应写入模板的主体。
3. `copyright_year` 或年份范围。
4. 若为自定义/商业许可证：用户提供最终法务文本，模型不得起草法律条款。

缺任一必需输入时不得开始。

## 状态转换规则

1. 用户选择标准 SPDX 许可证并给齐信息：`[!]` → `[/]`，执行本文件。
2. 用户明确选择“暂不添加/私有且不分发”：本任务改 `[-]`，发布清单明确 public release blocked。
3. 用户提供自定义法务文本：只按原文落盘和校验，不改写；无法确认完整性时继续 `[!]`。
4. 模型不得自行把状态改为 `[ ]` 或 `[x]`。

## 允许改动（解阻后）

1. 新增根 `LICENSE` 或用户指定的标准许可证文件名。
2. `README.md` 的许可证章节/徽章。
3. `CHANGELOG.md`。
4. `docs/06-环境运维/01-v0.4.0发布清单.md` 的许可证 gate。
5. 本任务和进度表状态。

## 禁止改动

1. 不自行选择许可证。
2. 不混合多个许可证，除非用户明确指定 dual-license 组合和连接词。
3. 不改写标准 SPDX 正文或添加模型生成的法律条款。
4. 不因 GitHub 仓库公开就推定开源授权。
5. 不执行发布/tag/push。

## 正向验证

1. LICENSE 正文与指定 SPDX 官方模板一致，仅许可的占位信息不同。
2. README 显示同一 identifier，链接到根 LICENSE。
3. CHANGELOG/发布清单记录真实决策。

## 反向验证

1. 用户未输入时根目录没有新 LICENSE。
2. 不存在默认 MIT 文本、示例 `Copyright (c) [year] [fullname]` 占位。
3. README/徽章/CHANGELOG 不出现与决策不同的许可证。
4. 不因本任务创建 tag 或 Release。
