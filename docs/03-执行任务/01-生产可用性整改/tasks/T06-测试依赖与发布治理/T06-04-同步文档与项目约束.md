## 当前行为

1. 根 README 存在错误文档坏链接、旧错误示例和过度能力宣称。
2. 包文档仍描述自动并行、CFB、RichError cause JSON、UA bot 判断等旧行为。
3. 根目录没有项目级 AGENTS.md 和 CHANGELOG.md，关键口径无法随代码演进。

## 固定文档产出

1. 根 README 是能力导航，不复制每个包全部细节。
2. 包说明是各 API 行为与迁移的事实来源。
3. AGENTS.md 是开发/执行约束事实来源。
4. CHANGELOG.md 是版本变化事实来源。

## 根 README 必须包含

1. 项目定位：Go 1.24 通用基础库，不是网络服务。
2. 模块清单与真实边界：JWT HS256、AES-GCM、验证码生成/比较、URL v2、pagination、errors、slice、ptr、UA 展示。
3. 每个安全敏感模块的限制：JWT 多实例 refresh 需共享原子 store；captcha 不含 TTL/限流；UA 非安全事实；URL 不代替授权。
4. 安装、最低 Go 版本和运行门禁命令。
5. 指向实际存在的包文档；错误文档链接改为 `errors/README.md`。
6. v0.4.0 migration/CHANGELOG 链接。
7. 不再使用“所有模块线程安全”“完整测试覆盖”“自动防重放”等绝对措辞。

## 项目级 AGENTS.md 必须包含

1. 当前技术栈：Go 1.24 module、无数据库/容器运行依赖。
2. 错误处理：包装 `%w`，判断统一标准 `errors.Is/As`，禁止 `err ==/!=`。
3. 安全不变量：JWT/URL/crypto/captcha/errors/UA 本轮固定设计摘要。
4. 调试与可观测性：不吞错、不用 fallback 掩盖；后台错误必须 reporter/返回值可见。
5. 测试门禁：test/race/vet/mod/coverage/govulncheck。
6. 任务文档与状态同步规则，链接到本任务入口。
7. 发布权限：执行模型不得 tag/push/release/选择许可证。
8. 文档随关键 API/技术方向同步更新。
9. 不复制全局无关约束；只保留本仓库适用内容。

## CHANGELOG 固定结构

采用 Keep a Changelog 风格，至少：

1. `# Changelog` 和说明。
2. `## [Unreleased]`。
3. `Added/Changed/Deprecated/Removed/Fixed/Security` 分类，只保留实际有内容项。
4. 逐项记录：JWT、URL、captcha/cursor、crypto、errors、slice/UA、CI/coverage/dependency。
5. 明确 breaking changes：URL legacy 不回退、短 key 失败、PasswordPolicy Config、slice LRU 删除、错误 Is 签名等。
6. 不写发布日期或 release URL；T06-05 形成候选清单，真正发布时再补。
