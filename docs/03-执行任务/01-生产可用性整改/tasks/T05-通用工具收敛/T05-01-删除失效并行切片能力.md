4. 数据产量：维护/性能预期；当前文档让调用方误以为公开 Filter/Map 会自动并行。

## 目标

删除没有任何调用者的私有 `containsParallel/filterParallel/mapParallel`，让文档只描述真实串行 API；`Sort` 改用标准库 `cmp.Ordered`，移除仅为 constraints 引入的 `golang.org/x/exp` 直接依赖。

## 允许改动

1. `slice/slice.go`。
2. `slice/slice_test.go`，仅在公共语义测试需要补充时修改。
3. `slice/使用说明.md`。
4. `go.mod`、`go.sum`，只允许 `go mod tidy` 因移除 x/exp 产生的变化。

## 禁止改动

1. 不新增公开 Parallel API、worker pool 或 context 版本。
2. 不把公开 `Filter/Map/Contains` 改成隐式并发。
3. 不改变公共函数的顺序、nil/empty 或结果语义。
4. 不升级其他依赖；统一留给 T06-03。

## 当前行为

1. 三个 parallel 函数均为私有，仓库没有调用点。
2. 文档多处宣称公开 Filter/Map 会对大切片自动并行，与实现不符。
3. `filterParallel` 合并结果时顺序不稳定，即使公开也会改变 Filter 契约。
4. `golang.org/x/exp` 只被用于 `constraints.Ordered`。

## 固定目标实现

1. 完整删除三个私有 parallel 函数及只为它们存在的 `runtime`、`sync` import。
2. `Sort` 改为：

   ```go
   func Sort[T cmp.Ordered](slice []T) []T
   ```

3. 导入标准库 `cmp`；不改变 Sort 返回副本的行为。
4. 运行 `go mod tidy` 后 `golang.org/x/exp` 不再是 direct 或 indirect 依赖；若仍由其他包真实需要，停止并记录调用点，不强删 go.sum。

## 正向测试

1. Contains/Filter/Map 对大、小切片结果一致且保持原顺序。
2. Sort 支持 int/string/float 等 cmp.Ordered 类型，并不修改输入 slice。
3. empty slice 行为与现有测试一致。

## 反向验证

1. `rg` 不再找到 private parallel symbols、runtime.NumCPU 或 WaitGroup。
2. `go list -m all` 不再包含 `golang.org/x/exp`。
3. slice 文档不再出现“自动并行”“自动切换到并行”等宣称。
