# T01-05 修复 F-AUTH-005 JWT 生命周期、配置与错误传播

状态：`[ ]`

## 来源

1. finding_id：F-AUTH-005。
2. Handoff：[JWT 生命周期和存储错误存在静默或并发契约缺口](../../../../08-安全审计/01-能力与安全评估交接/03-findings.md#f-auth-005--jwt-生命周期和存储错误存在静默或并发契约缺口)。
3. 权限类型：service/config-ops。
4. 数据产量：availability and AUTH capability。

## 目标

使 `TokenManager` 的构造、动态配置、后台清理和关闭在并发下可预测；外部存储错误必须通过返回值或显式 reporter 可见。

## 前置

1. T01-01～T01-04 已完成，字段布局以最新代码为准。

## 允许改动

1. `jwt/jwt.go`、`jwt/revocation.go`、`jwt/refresh_store.go`。
2. JWT 测试与 `jwt/使用说明.md`。

## 禁止改动

1. 不用 recover 吞 double-close 或竞态 panic。
2. 不让存储错误只在 EnableLog=true 时可见。
3. 不持锁调用外部 store、签名或 reporter。
4. 不用 0/false 同时表示“不支持、错误、空结果”。

## 目标 API 与约束

1. `JWTOptions` 增加 `ErrorReporter func(error)`；nil 时使用只输出错误摘要的默认 reporter，禁止包含 token/secret。
2. 新增 `CleanBlacklistContext(ctx) (int, error)` 和 `GetBlacklistSizeContext(ctx) (int, error)` 作为权威 API。
3. 旧 `CleanBlacklist()`、`GetBlacklistSize()`、`IsBlacklisted()` 保留时必须标记 `Deprecated`，错误交给 reporter，不作为内部默认调用。
4. `Shutdown` 使用 `sync.Once`。
5. 保留动态 setter 时统一使用 `configMu`；setter 对无效值返回 error。

## 当前行为

1. 多个动态 setter 与读路径没有统一同步。
2. Shutdown 重复 close channel 可 panic。
3. Clean/GetSize/IsBlacklisted 的无 error API 会吞掉外部 store 错误或把不同状态折叠成 0/false。
4. 后台错误是否可见依赖默认关闭的日志开关。

## 执行清单

- [ ] 为 mutable 配置增加统一锁；读取 `enableCache/cacheSize/cacheTTL/expiry/issuer/audience/log` 时取一致快照，禁止只锁 setter 不锁 reader。
- [ ] `SetCacheTTL(ttl)` 在 `ttl <= 0` 时返回 error；`SetCacheSize(size)` 在 `size <= 0` 时返回 error；`SetTokenExpiry` 拒绝未知 token type 和非正 duration。
- [ ] `NewTokenManager` 校验：access/refresh expiry > 0；cache enabled 时 size/TTL > 0；cleanup interval >= 0；reuse action 必须是已知枚举。自定义 options 零值导致错误是预期的 `v0.4.0` 破坏性变化。
- [ ] `Shutdown` 用 `sync.Once` 关闭 channel；无 ticker、重复调用和并发调用都不 panic。
- [ ] 后台 cleanup 调用 Context API；任何错误送入 `ErrorReporter`，不要受 `EnableLog=false` 影响。
- [ ] reporter 默认错误文本不包含原始 token、secret、验证码或 hash；测试使用注入 reporter 捕获调用。
- [ ] `CleanBlacklistContext` 对不支持 cleaner 返回 `(0,nil)`，对 store error 原样 `%w` 返回。
- [ ] `GetBlacklistSizeContext` 对不支持 sizer 返回明确 sentinel error，而不是用 0 混淆“不支持”和“空”。定义并测试该 sentinel。
- [ ] `IsBlacklisted` 文档明确 deprecated；新代码使用已有 `IsTokenRevokedContext`。
- [ ] 测试无效 config、每个 setter、重复/并发 Shutdown、后台 reporter、外部 store error。
- [ ] race 测试并发执行 Validate/Generate 与合法 setter，确保无 data race。
- [ ] 更新 `GetTokenExpiryConfig` 在锁内生成完整克隆，包含 T01-03/T01-04 新字段。

## 正向测试

1. 合法 setter 与 Validate/Generate 并发无 race，每次读到完整配置快照。
2. Shutdown 重复和并发调用均成功且不 panic。
3. Context API 返回 store 结果，后台 store error 触发 reporter。

## 反向测试

1. 非正 TTL/size/expiry、未知 token type/reuse action 构造或 setter 失败。
2. 不支持 size 的 store 返回明确 sentinel，不伪装为 0。
3. reporter/错误文本不包含 secret、完整 token、验证码或 hash。

## 不要做

1. 不用 recover 吞掉 double-close panic。
2. 不在错误发生时仅在 `EnableLog=true` 才记录。
3. 不用返回 0 表示“不支持”“错误”和“确实为空”三种状态。
4. 不持有配置锁跨越外部 store 调用或密码学签名，避免死锁和长临界区。

## 完成标准

1. 并发 setter/Validate/Shutdown 测试和 race 全部通过。
2. 外部存储故障在权威 API 中可被调用方判断，在后台路径中可被 reporter 观察。
3. 所有破坏性签名变化写入 JWT 文档的迁移段落。
