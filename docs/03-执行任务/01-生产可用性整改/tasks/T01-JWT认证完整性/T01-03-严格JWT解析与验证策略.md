# T01-03 修复 F-AUTH-003 严格 JWT 解析与验证策略

状态：`[ ]`

## 来源

1. finding_id：F-AUTH-003。
2. Handoff：[JWT 注册 claim 解析错误被忽略且算法约束过宽](../../../../08-安全审计/01-能力与安全评估交接/03-findings.md#f-auth-003--jwt-注册-claim-解析错误被忽略且算法约束过宽)。
3. 权限类型：service/token issuer。
4. 数据产量：AUTH capability。

## 目标

只接受合法、带 `exp` 的 HS256 token；注册 claim 类型错误必须可见；issuer/audience 的签发默认值与验证期望值明确分离。

## 前置

1. T01-01、T01-02 已完成。

## 允许改动

1. `jwt/jwt.go` 的 `StandardClaims.UnmarshalJSON`、`JWTOptions`、`DefaultJWTOptions`、`NewTokenManager`、`parseTokenClaims`。
2. `jwt/identity.go` 仅在配置克隆需要时修改。
3. JWT 测试与 `jwt/使用说明.md` 中对应配置说明。

## 禁止改动

1. 不增加 RSA/ECDSA/JWE 或多密钥轮换。
2. 不自动接受 HS384/HS512 或缺失 exp 的 legacy token。
3. 不把签发默认 Issuer/Audience 隐式当成验证期望。
4. 不用字符类别/熵 heuristic 拒绝长度合法的机器密钥。

## 公开 API 目标

1. `JWTOptions` 新增 `ExpectedIssuer string`。
2. `JWTOptions` 新增 `ExpectedAudience []string`。
3. `Issuer`/`Audience` 仍只控制默认签发 claims，不隐式成为验证期望。
4. secret 至少 32 字节；删除“至少三种字符类型”规则。

## 当前行为

1. StandardClaims.UnmarshalJSON 丢弃多个 registered claim getter error。
2. parser 只判断 SigningMethodHMAC，整个 HMAC family 都可通过。
3. exp 不是必需字段。
4. Issuer/Audience 同时承担签发默认和潜在验证语义，没有独立 expected 配置。

## 执行清单

- [ ] 在 `UnmarshalJSON` 中逐个检查 subject、issuer、audience、issued-at、expiration、not-before getter 的 error；错误文本包含 claim 名并使用 `%w`。
- [ ] 不允许 malformed `jti/type/sid` 静默变空：字段存在但类型不是 string 时直接返回错误；不保留数值 jti 兼容。
- [ ] `parseTokenClaims` 始终加入 `jwt.WithValidMethods([]string{jwt.SigningMethodHS256.Alg()})`。
- [ ] `validateClaims=true` 时加入 `jwt.WithExpirationRequired()`；expected issuer/audience 非空时加入对应 parser option。
- [ ] `validateClaims=false` 仅跳过时间/issuer/audience 验证，仍限制 HS256 且仍拒绝 claim 类型错误。
- [ ] `NewTokenManager` secret 校验改为 `len([]byte(secretKey)) >= 32`，删除字符类别统计。
- [ ] `GetTokenExpiryConfig` 返回 expected 配置的克隆。
- [ ] 测试 31 字节 secret 拒绝、32 字节 machine-generated/hex 合法密钥接受。
- [ ] 测试 HS384 token 即使使用同一 secret 也被拒绝。
- [ ] 测试缺少 exp、`exp:"invalid"`、非法 aud/iss 类型全部失败并保留可诊断错误。
- [ ] 测试 ExpectedIssuer/ExpectedAudience：匹配通过，不匹配失败；只设置签发默认值但不设置 Expected 时维持“仅签发默认”语义。
- [ ] 更新 `jwt/使用说明.md`，明确两个配置组和破坏性变化；不要在本任务修改根 README。

## 正向测试

1. 合法 HS256、exp、expected issuer/audience 匹配时通过。
2. 32 字节机器生成/十六进制风格 secret 通过。
3. validateClaims=false 仍限制 HS256 和 claim 类型，只跳过声明的语义校验。

## 反向测试

1. HS384/HS512、缺 exp、过期、malformed registered claim 全部失败。
2. ExpectedIssuer/Audience 不匹配失败。
3. 31 字节 secret 和数值 jti/type/sid 失败。

## 不要做

1. 不接受整个 HMAC family。
2. 不把 issuer/audience getter 错误忽略后当空值。
3. 不把 Issuer 默认值直接强制为 ExpectedIssuer，避免自定义签发 token 无法按显式策略处理。
4. 不用自制“字符种类”或 Shannon entropy 猜测替代密钥来源要求。

## 完成标准

1. 所有 malformed registered claim 测试失败关闭。
2. HS256/exp/expected issuer-audience 语义有正反测试。
3. 文档与新字段一致。
