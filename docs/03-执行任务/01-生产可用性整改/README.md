# 生产可用性整改

本文是整改任务入口。任务来源于能力与安全评估，目标是把 `utils-pkg` 从“功能较全但语义不稳”收敛为可被生产服务审慎依赖的 Go 基础库。

文档状态：T01–T05 与 T06-01–05/07 已由本地门禁验证为 `[x]`。T06-06 许可证决策已落盘为 MIT（`[/]`，待确认 LICENSE 正文）。

## 使用方式

1. 先读 [00-前置约束](00-前置约束.md) 和 [进度跟踪表](进度跟踪表.md)。
2. 再打开当前唯一 `[/]` 子任务所属任务组 README 和子任务文件。
3. 执行子任务中的 `<Context-Queries>`，重新确认文件和符号仍存在。
4. 只修改子任务“允许改动”列出的文件；需要新增路径时先更新任务文档和进度表。
5. 实现完成但未验证时改为 `[?]`；独立验证通过后才允许 `[x]`。
6. 一次只推进一个子任务。当前子任务未进入 `[x]` 或明确 `[!]`/`[-]` 前，不得启动下一个。

## 弱执行模型协议

1. 文档中的设计选择是约束，不是建议；不得自行更换算法、字段名、错误语义或兼容策略。
2. 不允许为了让测试通过而保留已知缺陷、放宽校验、吞掉错误或增加 legacy fallback。
3. 若代码已变化、API 不存在、测试与文档冲突，停止编码，把当前任务标 `[!]` 并写出精确差异。
4. 每个子任务建议由 Guide/强模型做短 prewalk：执行查询、确认调用点并完成第一笔生产修改，再交给弱 Executor。禁止把本 Markdown 当作冷启动模型的唯一事实来源。
5. 弱执行模型可以完成实现和本地验证，但不能自行批准许可证、发布、tag、push 或最终 `[x]`。

## 执行模型假设

1. 本文档用于跨会话恢复、进度权威和验收。
2. 同会话多模型成本路由使用 prewalk trajectory + todo + first edit，不使用“只读计划卡片”的冷启动模式。
3. R-fix 每次只接受一个子任务；R-verify 独立复核后更新最终状态。

## 设计边界摘要

1. 安全修复可以在 `v0.4.0` 做明确破坏性变更，但必须有迁移说明。
2. JWT 缓存、签名和 KDF 只能优化实现，不能改变凭证有效期或安全边界。
3. Go 错误链统一使用标准 `errors.Is/As` 和 `%w`。
4. 不新增远程基础设施；共享 refresh 消费仅定义接口和默认内存实现。
5. 不发布、不推送、不选择许可证。

1. 进度表除明确阻塞/暂缓项外全部 `[x]`。
2. 全量单测、竞态、vet、模块校验、覆盖率和安全依赖检查通过。
