# 前置约束

## 目标

1. 修复审计 Handoff 中的全部 confirmed Finding。
2. 让每项改动可由弱执行模型独立实施、由强模型独立验证。
3. 在不引入远程基础设施的前提下，建立生产可用的默认安全语义和明确扩展接口。

## 不做范围

1. 不新增数据库、Redis、消息队列、容器或网络服务。
2. 不在 macOS 本机安装/启动 PostgreSQL 或 Docker Engine。
3. 不实现完整 OTP 服务、设备指纹、RBAC 平台、JWE 或非 HMAC JWT 算法。
4. 不修改未在当前子任务列出的包。
5. 不做无基准支撑的性能重写。
6. 不保留默认不安全兼容回退。
7. 不 tag、push、发布或选择许可证。

## 项目定位

1. 产品形态：Go 1.24 通用工具 module，供下游服务导入。
2. 用户角色：库维护者、下游服务开发者、发布验证者；安全影响间接覆盖匿名用户和已登录用户。
3. 关键数据：JWT/session、密码/hash、密钥、签名 URL/cursor、验证码、error cause/context。
4. 信任边界：不可信 token/URL/hash/code 输入；可变返回对象；外部吊销/消费存储；JSON/日志输出。
5. 本次位置：`v0.3.0` 后的生产可用性整改，预期破坏性版本为 `v0.4.0`。

## 项目口径

1. 分支/环境：当前本地 `main` 与 `origin/main` 一致；实施应使用用户指定工作分支，若未指定不得自行 push。
2. Go：`go.mod` 为 1.24，当前验证 Go 1.26.5；代码不得依赖高于 1.24 的语言特性或标准库 API，除非同时提升 go directive 并获得用户确认。
3. 错误：使用 `%w`、标准 `errors.Is/As`；触及的测试也不得直接比较哨兵 error。
4. 日志：库不得直接 stdout 打印警告；不得记录完整 token、密码、hash、密钥或验证码。
5. 配置：无效配置应在构造/设置时返回错误，不得延迟到请求路径 panic。
6. API：破坏性安全变更进入 `v0.4.0` 迁移文档；禁止自动 legacy fallback。
7. 测试：本地只读/单元/fuzz/race 允许；远程主动测试禁止。
